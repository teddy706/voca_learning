# 프로젝트 브리프 — 단어콕(가칭)

## 1. 한 줄 요약
초등 3학년 쌍둥이 자녀의 학원 영단어 시험 대비를, 종이 단어장을 손으로 가리며 구두로 점검하던 방식에서 사진 등록(OCR) + 앱 기반 스펠링 점검으로 대체하는 PWA.

## 2. 문제
- 학원 단어장은 디지털 백데이터 없이 종이/사진으로만 존재한다.
- 현재 점검 방식(부모가 손으로 가리고 구두로 발음·스펠링 확인)은 수작업이고, 기록이 남지 않으며, 반복 출제가 불가능하다.
- 아이가 스스로 발음-스펠링 일치 여부를 확인할 방법이 마땅치 않다.

## 3. 해결 방향
1. 학원 단어장을 사진으로 찍어 OCR로 한글-영어 쌍을 자동 추출.
2. 추출 결과를 사람이 확인/수정한 뒤 자녀별 단어장(배치)으로 등록.
3. 한글을 보고 영어 스펠링을 맞히는 점검 모드(타이핑 또는 4지선다)로 기존 수작업을 대체.
4. 등록된 단어가 계속 쌓여 "단어은행"이 되고, 이를 기반으로 누적 랜덤 게임을 제공.

## 4. 타겟 사용자
- 초등 3학년 쌍둥이 자녀 (부모 계정 아래 자녀 PIN 프로필 2개)
- 부모 (등록 검수, 통계 확인)
- 타겟 디바이스: 아이폰 미니, 아이패드 미니 (PWA)

## 5. 목표
- Phase 1: 사진→OCR 등록 흐름과 스펠링 점검 모드로 기존 수작업을 1:1 대체
- Phase 2: 누적 단어은행 기반 가중 랜덤 게임 제공
- 인프라 비용을 기존 자매 프로젝트(리딩버디, twin-choice) 예산 안에서 흡수 — 새 유료 인프라를 늘리지 않는다

## 6. 범위

### 포함 (Phase 1)
- ~~사진 업로드 → Azure Document Intelligence OCR → 확인/수정 UI → 배치 등록~~ → **CSV 일괄 가져오기로 대체 완료**(2026-09-14, 아래 "제외" 참고)
- 점검 모드: 타이핑 응답 / 유사 스펠링 4지선다 응답 (세션 시작 시 선택)
- 문항·정답별 발음 재생 (Web Speech API)
- 부모 + 자녀(PIN) 모두 등록 가능, RLS로 자녀 간 데이터 격리
- 모든 시도 기록 저장 (`vocab_attempts`)

### 포함 (Phase 2)
- 단어은행 전체 대상 가중 랜덤 게임 (최근/빈도 기반 오답 가중치)
- 오답노트, 누적 정답률/스트릭 표시

### 제외 (이번 Phase 보류, 2026-09-14 결정)
- **사진 촬영 → OCR 등록**: 능률보카 중등기본 DAY 01~50 CSV로 등록을 대신하기로 해서 이번 Phase엔 불필요. 학원이 다른 책으로 바뀌거나 사진으로만 얻는 단어장이 생기면 재검토 — Blob/Document Intelligence 인프라는 이미 만들어둠.

### 제외 (의도적 보류, Phase 3 후보)
- 쌍둥이 간 랭킹/비교
- 정식 SRS(간격 반복) 알고리즘
- 학원마다 다른 단어장 레이아웃에 대한 범용 OCR 대응
- 리마인더 알림
- Blob Lifecycle Management(오래된 사진 자동 아카이빙)

## 7. 핵심 설계 결정 (요약)

| 항목 | 결정 |

## 8. 현재 상태 (2026-09-14)
- **Phase 0 완료, Phase 1(점검 기능 코드 작성) 진행 중.** `docs/` 4종 문서와 루트 `CLAUDE.md` 스캐폴딩 완료.
- Supabase 무료 슬롯 확인 완료(2/2 소진 → 리딩버디 프로젝트 공유로 확정, [PRD.md](PRD.md) 4.1.1).
- `vocab_words`/`vocab_batches`/`vocab_batch_items`/`vocab_attempts` 스키마 + RLS 마이그레이션을 리딩버디 Supabase 프로젝트에 적용 완료(에러 없음).
- Azure Blob Storage 계정(`vocakokphotos`)/컨테이너(`vocab-photos`, 비공개) 생성 완료, Document Intelligence는 리딩버디 기존 리소스 재사용 결정. `.env.local` 구성 완료. **단, 사진 OCR 등록 자체는 이번 Phase에서 제외하기로 해서 이 인프라는 당장 쓰지 않는다.**
- **단어 등록 완료**: 학원 시험 범위가 능률보카 중등기본과 같아서, 오디오 STT+PDF 정답지로 만든 CSV(`MP3_stt/voca_mp3/*_review.csv`, DAY 01~50)를 `scripts/import_vocab_csv.py`로 이 가족의 캐릭터 4명(고아린, 황유니, 아빠, 정보라) 전원에게 일괄 등록 완료 — 캐릭터당 고유 단어 876개, 배치 200개.
- 남은 Phase 1 항목: 점검 모드(타이핑/4지선다), 자녀 PIN 로그인 연동, 발음 재생, 반응형 확인.
- **점검 모드(복습+시험 3종+별 보상) 완성 후 `/code-review high` 1회 실시, 확정 10건 전부 수정 완료**(레이스 컨디션 4건, 접근 제어/일관성 2건, 방어적 코딩 4건) — 요구사항 변경 없이 견고성만 높인 작업. 상세는 [PRD.md](PRD.md) 4.10, [STORIES.md](STORIES.md) 에픽 7 참고.

## 9. 주요 리스크
- **비결정성**: 동일 오디오/이미지를 여러 번 처리해도 결과가 달라질 수 있음(4.7에서 실측 확인) — OCR 파이프라인에서도 유사 문제가 재발할 가능성을 염두에 두고, 확인 화면 UX를 정확도보다 우선시한다.
- **공유 Supabase 프로젝트 리스크**: 리딩버디와 같은 프로젝트를 쓰므로, 마이그레이션 실수가 리딩버디에 영향을 줄 수 있음 — 항상 기존 테이블 영향 여부를 먼저 확인.
- **자매 앱 확장 여력**: 세 번째 자매 앱을 만들 계획이 있다면 Supabase 무료 슬롯이 이미 소진돼 있어 Pro 업그레이드가 필요해질 수 있음(지금 결정 사항 아님).
